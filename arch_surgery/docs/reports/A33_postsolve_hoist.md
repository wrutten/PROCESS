## 1. Verdict

**The classification is derived, the driver refuses everything else, and the
strong gate holds on all three decks.** With the deck's committed
`postsolve_<scenario>.json` active, the entire solve phase is **bit-identical**
to the unmodified arm — because nothing the solve phase computes reads a
skipped output — and the per-call cost drops by exactly the suppressed call
sites:

| deck | post-solve set | `call_models` | solve-phase node calls, WITHOUT → WITH | suppressed (per node) | saving |
|---|---|---|---|---|---|
| `large_tokamak_nof` | vacuum, water_use, costs | 660 | 42 772 → 39 206 | 3 566 (vacuum 2 246, water_use 660, costs 660) | **8.34 %** |
| `low_aspect_ratio_DEMO` | vacuum, water_use, costs | 1 050 | 68 947 → 63 189 | 5 758 (vacuum 3 658, water_use 1 050, costs 1 050) | **8.35 %** |
| `st_regression` | pulse, vacuum, water_use, costs | 570 | 37 312 → 33 086 | 4 226 (pulse 1 132, vacuum 1 954, water_use 570, costs 570) | **11.33 %** |

Every percentage holds **for one full `A1'` optimisation from the deck's own
unperturbed baseline start at τ = 1e-6 on the a26-mode spec** — one run per
arm per deck, exact counts, not a sampled statistic (trap T11: the condition
in the same sentence as the number). Per `call_models`, the saving decomposes
as ~1.0 call each for `water_use` and `costs` (the once-per-call FF tail),
~3.4 calls for `vacuum` (one per M3 inner sweep) and ~2.0 for `pulse` on
`st_regression` (one per outer pass) — multipliers that follow the trajectory's
sweep counts and are not constants of the deck.

## 2. The classification (deliverable i) — derived, not asserted

Committed artifacts (`arch_surgery/docs/data/postsolve_<scenario>.json`,
generated by the `classify` stage at clean `3820fa5d`, committed `68f87163`):

**Seeds.** Per deck: the objective's read set — the deck's `minmax` branch of
`objective_function` by AST (`large_tokamak_nof` = 1 → `physics.rmajor`;
`low_aspect_ratio_DEMO` = −14 → `times.t_plant_pulse_burn`; `st_regression` =
−5 → `current_drive.big_q_plasma`) — plus every active constraint's read set,
per `icc`, by AST over `constraints.py` with closure over local helper calls.
The deck's `icc` list is parsed from the frozen scenario deck with a
comment-proof matcher; the cross-check the brief demanded: parsed base counts
26 / 25 / 18, plus exactly one for `icc = 93` on the pulsed decks (the lifted
deck the `A1'` arm actually runs, which is where A28's records come from),
equal A28's recorded `n_constraints` **27 / 26 / 18 — PASS on all three**, and
the recorded `i_figure_merit` matches the parsed `minmax` on all three. Seed
sizes: 85 / 86 / 63 distinct fields.

**Backward crawl.** Writer authority is the committed run-time write census
(`node_writesets.json`, per scenario; output()-path traffic excluded at
source, traps T1/T7). Transitive reachability comes from the sibling
repository's dependency exports — `output/tokamak/process_dependencies.json`
for `large_tokamak_nof` (the analysis preset, which matches that deck exactly;
node-map caveat V6, resolved by their per-scenario regeneration M100) and the
per-deck exports for the other two. Read-only; sha256 and their git head
(`2b4fea1c`) recorded in each artifact at read time, so a later regeneration
of their exports is visible rather than silent (trap T9, accepted here on the
task brief's explicit instruction). The analysis pin (`PROCESS_at_36ac820e`)
is read from their config at run time, never copied. Fixpoint rule: a unit is
NEEDED iff its measured writes intersect the consumed field set; a needed
unit's DSM reads join that set; every unit never needed is a candidate. Helper
file-models' reads are attributed to **every** transitive caller —
over-attribution can only add needed nodes, never hide a reader.

**What the crawl found, against the first cut:**

- `costs` + `water_use` leave on all three decks — **first cut confirmed.**
  No objective among 1/−14/−5 reads a cost output; the constraint layer
  touches `data.costs.*` only at `f_t_plant_available` (icc 61, active
  nowhere here, and unwritten at runtime on these decks) and `cplife`
  (icc 85, active nowhere here; written by `availability`, and only on
  `st_regression`).
- `pulse` stays per-call on both pulsed decks — **first cut confirmed**: its
  measured write `times.t_plant_pulse_burn` is read by fom −14
  (`objectives.py:81`), by icc 13, and by icc 93 on the lifted arm.
- **Beyond the first cut, `vacuum` leaves on all three decks.** Its five
  measured writes (`vacuum.dia_vv_vacuum_ducts`, `dlscal`,
  `m_vv_vacuum_duct_shield`, `n_vac_pumps_high`, `n_vv_vacuum_ducts`) are
  read by exactly two things in `process/`: the 1990 cost model — itself
  post-solve, and later in sequence order — and `availability`'s
  `avail_2`/`avail_st`/`calc_u_unplanned_vacuum`, which are reachable only
  from `i_plant_availability` = 2/3 while **all three decks set
  `i_plant_availability = 0`** (the V6 branch-liveness check, resolved per
  site and recorded in the artifact).
- **Beyond the first cut, `pulse` leaves on `st_regression`.** Its measured
  write set there is empty (`i_pulsed_plant = 0`; A25 §2.3's measurement) —
  a node with no outputs trivially has none the optimiser consumes.

**Why everything else stays** (each recorded with the consuming reader in the
artifact): `availability` writes `divertor.pflux_div_heat_load_mw` (read
in-loop) and, on `low_aspect_ratio_DEMO`, `costs.bktcycles` — **a direct seed
read**: icc 90 (CS fatigue) reads it at `constraints.py:1904`. `structure`
feeds `power`; `cryostat` feeds `buildings`/`structure`; `buildings` feeds
`power.acpow`; `vacuum_vessel` feeds `ccfe_hcpb`/`cryostat`; and so on — the
full `needed` map with per-field consumers is in each artifact's `crawl`
block.

**Confirmation in source.** An AST scan over `process/` for every
candidate-written field (126 across the union), every external read site
classified: candidate-internal, inactive objective branch (fom 6/7/15),
inactive constraint, availability branch dead under the deck's switch,
stellarator/IFE path, or the one genuine oddity — `evaluators.py:80` formats
`costs.coe` into a `logger.debug` f-string every `fcnvmc1`, which reads a
stale float into a string and feeds no computation. An unclassifiable site
fails the stage (that tooth never fired). The artifact also spot-checks trap
T1's own edge: no export attributes a `physics.b_plasma_vertical_required`
read to the run path.

**Hazard checked, not assumed:** excluding a node freezes its ystate
components at process defaults for the whole solve, and the coupling-state
predicate scores a component that is non-float-viewable or NaN as `inf`
(A25's lesson). All ~125 frozen components per deck were checked against a
fresh process: every default is a finite scalar, so a frozen component
contributes exactly 0 to every residual. The `fullrun` gate then confirmed
the sweep counts are untouched.

## 3. The driver capability (deliverable ii)

`PROCESS_ARCH_POST_SOLVE=<path to postsolve_<scenario>.json>` (VP2c in
`process/core/caller.py`; driver scope only, nothing under `process/models/`
touched). When set: every listed node is skipped at its solve-phase `_node`
call site (counted, per node), and executed **exactly once** in
`write_output_files` — after the optimiser accepts, before any output work —
by the existing block-sweep mechanism at the accepted x, which is the same
inject-and-sweep pattern the output path applies to every node. The one-shot
lands after the solve-phase counter freezes, so the skipped nodes' calls are
visible in `node_calls_total` and absent from `node_calls_solve_phase`. The
output phase and the exit audit run on their own Callers, which never enter
`call_models`, so they still run everything — the audit stays the same
instrument in every arm.

The loader refuses rather than trusts, and each refusal was **shown to fire**
(`validation` stage, fresh subprocess each, 4/4 refused at the first
`call_models` before any model ran):

| probe | check that fired |
|---|---|
| hand-edited artifact (node appended, sha not regenerated) | `nodes_sha256` rebuild — "does not rebuild" |
| wrong deck (`large_tokamak_nof` artifact on `st_regression`) | `i_figure_merit` against the run's own numerics — "wrong deck" (the active-`icc` check backs it) |
| `pulse` listed on `large_tokamak_nof` (sha regenerated, so only this check can refuse) | measured writes × predicate-layer reads — "this deck keeps 'pulse' per-call" |
| unknown node (sha regenerated) | committed node map — "not `_call_models_once` call sites" |

Unset, every hook is a no-op (`_post_solve` stays `None` on every path).

## 5. What is *not* claimed

- **No wall-clock claim.** The two arms' wall times are within noise of each
  other and are printed as progress information only; the acceptance
  quantities are counts and hex comparisons throughout.
- **The saving percentages are single-trajectory numbers.** They are exact
  for the baseline start of each deck under `A1'`; the multi-start
  distribution and the Phase-B effect under the full V2 arm (A2: no outer
  loop, so `vacuum`'s M3-inner multiplier will differ) are V2's measurements,
  not this task's.
- **The classification is per-deck and per-arm by construction.** The loader
  pins it to the deck's `i_figure_merit` and active `icc` set; a deck naming
  fom 6/7/15, icc 61/85/90-with-costs-writers, `i_plant_availability` ≥ 2, or
  icc 9/41 would legitimately classify differently and must be re-derived,
  not reused.
- **The solve-phase predicate does read frozen candidate components** (the
  ystate spec contains ~125 of them per deck). This task shows they
  contribute zero at finite defaults and that no sweep count moved on these
  trajectories; it does not prove no trajectory exists where a `vacuum`
  component would have been the binding residual in the WITHOUT arm. The
  full-run gate is the per-deck detector for exactly that, and it is part of
  the capability's acceptance wherever the exclusion is re-derived.
- The `evaluators.py` debug f-string means a WITH-arm run with DEBUG logging
  enabled would print stale `costs.coe` values; nothing numeric consumes
  them.
